# NNY 坦克大战 · 浩源 · 浪尖儿社区

经典四方向坦克游戏，保留「NNY出品」「浩源」「浪尖儿大学生社区 / 浪尖儿社区」品牌内容。支持单人守卫、同机双人合作、好友 1v1、快速排位。

## 启动

需要 Node.js 20 或更新版本，无需安装 npm 依赖。

```sh
node server.js
```

然后访问 **http://localhost:8000**。Windows 可双击 `start-game.cmd`。也保留 `python tank_server.py` 启动入口，Python 入口会调用 Node.js，不再单独运行旧版 HTTP 服务。

- `/`、`/index.html`、旧版 `/tank.html` 均可访问。
- 同 Wi-Fi 设备使用终端打印的局域网地址；不要在手机中填写 `localhost`。
- `PORT` 修改端口，`HOST` 修改监听地址，默认监听 `0.0.0.0:8000`。
- 本地服务器停止后联机不可用。关闭窗口或 Ctrl+C 可停止服务。
- 直接双击 `index.html` 可以体验本地模式，联机与排行榜需要服务器。

## 玩法

| 模式 | 规则 |
| --- | --- |
| 单人守卫 | 保护 3 点耐久的基地，完成 5 波敌人；队伍生命用尽或基地被毁则失败 |
| 同机合作 | 两位玩家共用生命，一起守卫基地；需要键盘，手机触控控制 P1 |
| 好友 1v1 | 创建房间，复制邀请链接或输入 6 位邀请码；双方准备后自动开局 |
| 快速排位 | 等待另一名真实玩家进入快速排位，匹配成功自动开局；目前为先到先匹配 |

竞技每局 **3 分钟，率先击毁对手 3 次获胜**。超时先比较击毁次数，再比较剩余血量百分比（例如 3/3 与 4/4 均为 100%），都相同则平局。阵亡后约 1.6 秒复活，出生保护 1.5 秒。

双方同意再战后自动轮换地图。再战属于好友切磋，不继续计排位，以区分自由切磋与独立排位。

## 2.1 体验优化

- 双方载入并绘制战场后，同步倒计时 3 秒。倒计时期间禁止移动、射击和技能，不占 180 秒作战时间。
- 快速排位可选择「边练边等」；匹配成功自动转入对局，也可取消匹配后继续练习。
- 首次进入提供可跳过的三步互动教学，可从作战指南重玩或进入自由练习。
- 转弯容错、220ms 路口转向缓冲及方向短按缓存；对齐和移动均做碰撞检查。
- 命中、格挡、击毁反馈；自己的战车和 HUD 标记「你」；工程掩体绿色/红色预览与失败原因使用同一套规则。
- 选车卡显示生命、移速、射击间隔、技能冷却；车长档案显示四个专精任务及最近 8 场战绩。
- 专精奖励只用于本地收藏，完成对局后累计；教学和练习不计奖励，重复读取同一结算不重复奖励。主动退出的联机对局也记录战绩。

## 操作

| 玩家 | 移动 | 射击 | 技能 |
| --- | --- | --- | --- |
| 单人 / 联机 | WASD 或方向键 | 空格 / J | E |
| 同机 P1 | WASD | J | E |
| 同机 P2 | 方向键 | Enter / `/` | 右 Shift |
| 手机 | 屏幕四方向按钮 | 右侧射击，支持按住连射 | 技能按钮 |

P / Esc 暂停本地游戏；M 开关音效。失焦或切到后台会清空输入，本地对局自动暂停。联机对局不能由一方暂停；正式开局后掉线超过 12 秒或主动退出判负；载入/倒计时阶段取消不计分，载入超过 20 秒自动取消。

## 战车与地形

| 战车 | 特点 | 技能 |
| --- | --- | --- |
| 疾风 | 3 点生命，速度快 | 推进冲刺，不可穿越障碍 |
| 磐石 | 4 点生命，移动与装填较慢 | 正面护盾 2 秒，侧后方仍可受击 |
| 筑垒 | 3 点生命，装填快 | 前方临时掩体 5 秒，可承受 2 发炮弹 |

三张竞技地图均采用旋转对称布局。砖墙可破坏；钢墙不能破坏；水域阻挡坦克但允许炮弹通过；草丛为视觉掩饰，不提供真正隐身。友方炮弹不会伤害队友或基地。

## 成长和排行榜

- 熟练度用于收藏坦克：疾风默认收藏，120 收藏磐石，260 收藏筑垒。所有坦克可以试玩，排位全部开放；收藏不增加战斗数值。
- 本地守卫熟练度、最佳得分、选车、音效设置存入浏览器。
- 快速排位按服务器判定的胜负计算 Elo 积分（初始 1000，K=24），并奖励熟练度；好友房和单人模式不计入排行榜。
- 排行榜展示**当前服务器**的真实排位记录，不是全球榜，也没有填充虚构玩家。
- 游客凭据保存在浏览器。清除浏览器数据会丢失档案访问凭据；当前没有注册、跨设备账号找回或游客合并功能。
- 服务器保存 `data/profiles.json`，定期及正常关闭时落盘；该目录不通过 HTTP 暴露。

## 开发结构

```text
engine.js        共用规则与固定 60 Hz 逻辑模拟
server.js        权威模拟、房间、输入接口、排位与存档
progress.js      本地专精、一次性奖励与最近战绩
client.js        浏览器 UI、输入、Canvas 渲染、本地模式
style.css        桌面与手机响应式布局
index.html       游戏入口与品牌内容
tests/           规则和 HTTP 集成测试
backups/         原始 HTML 与 Python 服务端备份
docs/            竞品来源、开发进度和验收记录
```

联机客户端仅提交方向、射击、技能及单调递增序号。移动、命中、地形破坏、血量和胜负均由服务器判定；短按操作采用序号缓存，避免轮询之间丢失。当前使用串行 HTTP 状态同步，目标约 20 次/秒，并保留断线重试；不是 WebSocket 架构。

## 验证

```sh
node --test tests/*.test.js
```

覆盖帧率一致性、双方命中、技能、基地保护、地图连通性、胜负、静态资源限制、房间权限、输入序号与短按、断线/离开、再战、积分和存档。

## 公网部署边界

当前项目可本地和局域网游玩，未自动购买服务器或部署公网。部署时运行常驻 Node 服务，通过反向代理提供 HTTPS，保留 Host 头，并设置 `PUBLIC_URL=https://你的域名`，让复制的邀请链接使用公网地址。使用独立可备份的数据目录与持久磁盘。

当前为单进程版本，房间位于内存中；服务重启不恢复正在进行的对局。正式扩大用户量前，还需要弱网与并发压测、完善账号体系、匹配分段、防刷分和观测告警。当前同机双端验证不能代替真实手机设备和公网弱网测试。
