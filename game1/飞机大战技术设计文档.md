## 1. 项目概述

### 1.1 产品定位
一款**纯前端、零依赖后端、即开即玩**的科幻风格纵向卷轴射击游戏（Vertical Scrolling Shooter）。

### 1.2 核心特色
| 维度 | 描述 |
|------|------|
| 美术风格 | 赛博朋克 + 霓虹科技风，深空背景 + 粒子特效 |
| 玩法多样性 | 4 种武器 / 3 种主动技能 / 5 种敌机 / 3 个 Boss |
| 核心挑战 | 弹幕躲避 + Boss 机制战 + 装备养成 |
| 上手难度 | 30 秒上手，渐进式难度曲线 |
| 单局时长 | 普通 3~5 分钟，Boss 战 1~2 分钟 |

### 1.3 参考玩法融合
- **雷电式**纵向卷轴基础手感
- **东方Project式**弹幕躲避（Boss 弹幕形态切换）
- **合金弹头式**道具掉落与武器切换
- **吸血鬼幸存者式**局内升级三选一（Rougelite 养成）

## 2. 技术栈选型

### 2.1 推荐方案
```
渲染层：HTML5 Canvas 2D（无第三方引擎，便于 Solo 维护）
语言：   TypeScript（强烈推荐，类型安全避免运行时崩溃）
构建：   Vite（秒级热更新，零配置）
音频：   Web Audio API（原生，无需音频库）
存储：   localStorage（存档、最高分、解锁状态）
部署：   纯静态文件，可托管 GitHub Pages / Vercel / Netlify
```

### 2.2 为什么不用 Phaser / PixiJS？
- Solo Builder 维护成本：原生 Canvas 更可控，调试链路短。
- 包体积：原生方案 < 50KB，框架方案普遍 > 200KB。
- 学习曲线：避免被框架 API 反噬，专注于玩法本身。
- 若后续需要 WebGL 加速，可平滑迁移到 PixiJS（接口风格相近）。

### 2.3 可选增强库（按需引入）
| 库 | 用途 | 引入时机 |
|----|------|---------|
| `howler.js` | 音效播放封装 | 若原生 Web Audio 烦琐 |
| `tweakpane` | 调参面板 | 开发期调试数值平衡 |

## 3. 整体架构设计

### 3.1 分层架构
```
┌─────────────────────────────────────────┐
│  UI 层 (HUD / 菜单 / 升级面板)           │  DOM + Canvas 叠加
├─────────────────────────────────────────┤
│  游戏逻辑层 (Game State Machine)         │  状态机驱动
├─────────────────────────────────────────┤
│  系统层 (Scene / Entity / Physics / Input)│  ECS-lite
├─────────────────────────────────────────┤
│  渲染层 (Renderer / Particle / Camera)   │  Canvas 2D
├─────────────────────────────────────────┤
│  资源层 (Asset / Audio / Storage)        │  Loader + Cache
└─────────────────────────────────────────┘
```

### 3.2 游戏状态机（FSM）
```
Boot → Loading → MainMenu → Playing → Paused
                                  ↓
                              GameOver → MainMenu
                                  ↓
                            Victory → MainMenu
```
**关键点**：每个状态独立 `enter()/exit()/update(dt)`，避免状态污染。

### 3.3 主循环（Fixed Timestep）
```typescript
// 固定逻辑步长 60FPS，渲染跟随 requestAnimationFrame
const FIXED_DT = 1000 / 60;
let accumulator = 0;
let lastTime = performance.now();

function loop(now: number) {
  const frameTime = Math.min(now - lastTime, 250); // 防止切后台后跳跃
  lastTime = now;
  accumulator += frameTime;
  while (accumulator >= FIXED_DT) {
    update(FIXED_DT / 1000);  // 逻辑更新（秒）
    accumulator -= FIXED_DT;
  }
  render(); // 渲染插值
  requestAnimationFrame(loop);
}
```
**为什么固定步长**：物理与碰撞行为可复现，避免高刷新率屏幕难度异常。

## 4. 核心引擎系统

### 4.1 实体系统（ECS-Lite）
不引入完整 ECS 框架，使用**组合 + 标签**轻量方案：

```typescript
interface Entity {
  id: number;
  tags: Set<string>;          // 'player' | 'enemy' | 'bullet' | 'particle' ...
  active: boolean;
  transform: { x: number; y: number; rotation: number };
  velocity: { x: number; y: number };
  collider?: { w: number; h: number; radius: number };
  health?: number;
  render?: (ctx: CanvasRenderingContext2D) => void;
  update?: (dt: number) => void;
}
```

### 4.2 场景管理
```typescript
interface Scene {
  entities: Entity[];
  spawnEnemy(): void;
  update(dt: number): void;
  render(ctx: CanvasRenderingContext2D): void;
}
```
单场景内通过对象池管理实体，避免频繁 GC。

### 4.3 对象池（关键性能优化）
```typescript
class ObjectPool<T> {
  private free: T[] = [];
  constructor(private factory: () => T, private reset: (t: T) => void) {}
  acquire(): T { return this.free.pop() ?? this.factory(); }
  release(t: T) { this.reset(t); this.free.push(t); }
}
```
**必须池化的对象**：子弹、粒子、敌机。否则同屏 500+ 子弹会触发严重 GC 卡顿。

### 4.4 碰撞检测
- **粗筛**：基于网格分区（Spatial Hash Grid），仅检测相邻格子。
- **精筛**：圆形碰撞（速度快，适合飞机外形）。
```typescript
function collide(a: Entity, b: Entity): boolean {
  const dx = a.transform.x - b.transform.x;
  const dy = a.transform.y - b.transform.y;
  const r = a.collider!.radius + b.collider!.radius;
  return dx * dx + dy * dy < r * r;
}
```

### 4.5 输入系统
| 输入方式 | 行为 |
|---------|------|
| 键盘 WASD / 方向键 | 移动 |
| 空格 | 射击（按住连发） |
| J / K / L | 释放 3 个主动技能 |
| Shift | 慢速精确移动（弹幕躲避神技） |
| Esc / P | 暂停 |
| 鼠标拖动 | 备用：触屏支持 |

**实现要点**：维护 `Set<string>` 按键状态，每帧轮询而非事件驱动，避免按键丢失。

## 5. 玩家系统

### 5.1 玩家属性
```typescript
interface Player extends Entity {
  hp: number; maxHp: number;
  shield: number; maxShield: number;     // 护盾，先于血量受损
  speed: number; slowSpeed: number;
  weaponLevel: number;                    // 1~5 级
  currentWeapon: WeaponType;
  ownedWeapons: Set<WeaponType>;
  skills: SkillSlot[];                    // 3 个主动技能槽
  exp: number; level: number;
  invincibleTime: number;                 // 受击无敌帧
  bombs: number;                          // 屏幕清屏炸弹数
}
```

### 5.2 受击与无敌帧
- 受击后 `invincibleTime = 1.5s`，期间闪烁且可穿越子弹。
- 护盾归零后才开始扣血，护盾脱战 3 秒后自动回复。
- 死亡 → 触发爆炸特效 → 进入 GameOver 状态。

### 5.3 升级系统（Rougelite）
- 击杀敌人获得经验，满经验升级 → **暂停游戏，弹出三选一面板**。
- 升级选项池示例：
  - 武器升级（伤害 +20%）
  - 新增武器槽（解锁第 4 种武器）
  - 护盾上限 +50
  - 移动速度 +15%
  - 技能冷却 -20%
  - 子弹散射 +1
- 每次三选一，玩家局内 build 自由成长。

### 6.2 敌机数据结构
```typescript
interface Enemy extends Entity {
  type: EnemyType;
  hp: number;
  fireTimer: number;
  fireInterval: number;
  movePattern: MovePattern;   // 'straight' | 'sine' | 'track' | 'cruise'
```

### 6.3 行为脚本（Script 驱动）
每种 MovePattern 是独立函数，便于扩展：
```typescript
const MovePatterns = {
  sine: (e: Enemy, t: number) => {
    e.transform.x += Math.sin(t * 3) * 2;
    e.transform.y += e.velocity.y;
  },
  track: (e: Enemy, t: number, player: Player) => {
    const dx = player.transform.x - e.transform.x;
    e.transform.x += Math.sign(dx) * Math.min(Math.abs(dx), 1.5);
    e.transform.y += e.velocity.y;
  },
};
```

### 6.4 刷怪系统（Wave Director）
```typescript
interface Wave {
  time: number;             // 触发时间（秒）

interface SpawnInstruction {
  enemyType: EnemyType;
  count: number;
  formation: 'line' | 'V' | 'random' | 'circle';
  interval: number;         // 间隔生成时间

```
**关键点**：刷怪表用数据驱动（JSON 配置），方便调关卡而不改代码。

## 7. Boss 系统（核心卖点）

### 7.1 Boss 设计原则
- **多阶段**：血量分 3 段，每段切换弹幕形态与攻击模式。
- **机制战**：不靠血量堆砌，靠躲避弹幕找输出窗口。
- **视觉冲击**：体积大（占屏 1/4），出场动画 + 震屏 + 警告条。
- **弱点系统**：特定部位可破坏，破坏后解锁更高伤害输出。

### 7.2 Boss 数据结构
```typescript
interface Boss extends Enemy {
  phase: number;                    // 0/1/2 三阶段
  phaseThresholds: [number, number]; // 血量阈值 66% / 33%
  parts: BossPart[];                // 可破坏部位
  patterns: BulletPattern[][];      // 每阶段多套弹幕
  patternIndex: number;
  patternTimer: number;
  enrageTimer: number;              // 狂暴计时（超时强制进入下一阶段）
}
interface BossPart {
  name: string;                     // 'leftCannon' | 'core' | 'rightWing'
  hp: number;
  destroyed: boolean;
  offset: { x: number; y: number };
}
```

### 7.3 弹幕模式库（BulletPattern）
设计可复用弹幕函数，组合出 Boss 各阶段：

| 模式名 | 描述 |
|-------|------|
| `ringBurst` | 全方位环形弹幕 |
| `spiral` | 螺旋持续弹幕 |
| `aimedStream` | 瞄准玩家连射 |
| `wallGap` | 弹墙留缝（必须穿过缝隙） |
| `crossFire` | 十字交叉弹幕 |
| `homingMissile` | 追踪导弹（可被击落） |

```typescript
type BulletPattern = (boss: Boss, dt: number) => void;

const Patterns: Record<string, BulletPattern> = {
  ringBurst: (boss, dt) => {
    boss.patternTimer -= dt;
    if (boss.patternTimer <= 0) {
      const count = 24 + boss.phase * 8;
      for (let i = 0; i < count; i++) {
        const angle = (i / count) * Math.PI * 2;
        spawnBullet(boss.transform, angle, 180);
      }
      boss.patternTimer = 1.2;
    }
  },
  // ...
};
```

### 7.4 Boss 战节奏控制
- **出场**：屏幕顶部红警横条 + "WARNING" 文字 + 震屏 2 秒。
- **阶段切换**：血量跨阈值时全屏闪白 + Boss 短暂无敌 1 秒 + 切换弹幕组合。
- **死亡**：连续爆炸特效 3 秒 + 慢镜头 + 战利品大量掉落。

### 7.5 Boss 阵容（3 关 3 Boss）
| Boss | 主题 | 机制亮点 |
|------|------|---------|
| BOSS-1 「铁壁」 | 重型炮台 | 弹墙留缝 + 部位破坏 |
| BOSS-2 「幻影」 | 分身术 | 3 个分身同时弹幕，找真身 |
| BOSS-3 「终焉」 | 最终形态 | 三阶段全程弹幕秀 + 狂暴时限 |

### 10.4 主菜单设计要点

- 背景：滚动星空 + 玩家飞机预览旋转。
- 按钮：玻璃拟态 + 悬停辉光。

## 12. 音效系统

### 12.1 音效清单
| 类别 | 事件 | 风格 |
|------|------|------|
| BGM | 主菜单 / 战斗 / Boss | 电子合成器、节奏感强 |
| SFX | 射击 | 短促"啾"声 |

### 12.2 实现要点
- 使用 `AudioContext` 创建音源，避免 `<audio>` 标签的延迟。
- BGM 与 SFX 分通道，独立音量控制。
- 提供「静音」开关，默认 BGM 关闭（用户主动开启，避免一进页面就吵）。

### 13.3 资源加载
- 所有音效用 `decodeAudioData` 预解码到内存。
- 加载阶段显示进度条，全部完成才进入主菜单。

## 14. 性能优化清单

| 渲染 | 关闭 `imageSmoothingEnabled`（像素感）或按需开启 |
| 渲染 | 静态背景预渲染到离屏 Canvas |
| 渲染 | 同色子弹批量 `fillRect`，减少 `fillStyle` 切换 |
| 逻辑 | 子弹/粒子使用对象池 |
| 逻辑 | 碰撞检测用空间哈希网格 |
| 逻辑 | 屏幕外实体立即回收 |
| 内存 | 限制粒子上限（800），超出按 FIFO 淘汰 |
| 内存 | 图片资源用 `createImageBitmap` 缓存 |
| 帧率 | 主循环固定步长，渲染插值 |
| 帧率 | `requestAnimationFrame` 暂停时停止逻辑累积 |

### 14.1 性能预算
- 目标：60 FPS @ 1080p，同屏 500 子弹 + 300 粒子流畅。
- 降级策略：检测帧率 < 45 持续 2 秒，自动降低粒子数与子弹光晕。

## 18. 关键风险与规避

| 风险 | 规避措施 |
|------|---------|
| 同屏子弹过多导致卡顿 | 对象池 + 空间哈希 + 粒子上限 |
| Boss 弹幕难度过高劝退 | 提供"简单模式"，弹幕密度自适应玩家死亡次数 |
| Solo Builder 范围失控 | 严格按里程碑推进，M5 之前不碰 M6 内容 |
| 数值失衡 | 集中在 `balance.ts`，便于调参 |
| 音频自动播放被浏览器拦截 | 用户首次点击"开始游戏"后才创建 AudioContext |
| 移动端性能差 | 提供"性能模式"开关，关闭粒子与光晕 |

## 19. 验收 Demo 标准（MVP）

最小可玩版本应满足：
- [ ] 玩家可移动、可射击
- [ ] 至少 2 种敌机出现
- [ ] 至少 1 种武器可升级
- [ ] 1 个 Boss 可挑战
- [ ] 死亡 → 重开 流程闭环
- [ ] 60 FPS 稳定（同屏 200 子弹内）
